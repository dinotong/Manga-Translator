# Decision Log

> บันทึกการตัดสินใจที่ทำไปเองโดยไม่ได้ถามเจ้าของโปรเจกต์ พร้อมเหตุผล
> **เจ้าของอ่านย้อนหลังแล้วสั่งกลับได้ทุกข้อ** — ถ้าไม่เห็นด้วยข้อไหน บอกได้เลย จะแก้ให้
>
> รูปแบบ: ตัดสินใจอะไร · ทำไม · ทางเลือกที่ไม่เลือกและทำไม · ย้อนกลับยากแค่ไหน
> เรียงใหม่สุดอยู่บน · ADR ที่ยาวกว่านี้แยกเป็นไฟล์ของตัวเอง (เช่น `ADR-001`)

## D-008 · ปุ่มดาวน์โหลด PNG หาขนาดฟอนต์ด้วย binary search ไม่ใช่สูตร
**2026-08-15 · `spike/src/ui/export-png.ts`**

ตอนวาดลง canvas ใช้ binary search หาขนาดฟอนต์ที่ใหญ่ที่สุดที่ยังพอดีกล่อง แทนที่จะใช้สูตรประมาณแบบที่ overlay บนหน้าจอใช้

**ทำไม:** บนหน้าจอมี CSS (`overflow:hidden`) คอยตัดข้อความล้นให้ สูตรประมาณจึงพอ แต่บน canvas **ไม่มีอะไรตัดให้** ถ้าประมาณพลาดตัวอักษรจะไปโผล่นอก bubble ทับภาพ ซึ่งแย่กว่าฟอนต์เล็กไปนิดหน่อย

**ไม่เลือก:** ใช้สูตรเดียวกับ overlay — เร็วกว่าแต่เสี่ยงล้น · ใช้ html2canvas — เพิ่ม dependency มาทำสิ่งที่เรารู้พิกัดอยู่แล้ว

**ย้อนกลับ:** ง่าย ไฟล์เดียว

## D-007 · ตัดบรรทัดภาษาไทยทีละตัวอักษร
**2026-08-15 · `spike/src/ui/export-png.ts`**

**ทำไม:** ไทยไม่มีช่องว่างระหว่างคำ ถ้าตัดตามช่องว่างจะได้บรรทัดเดียวยาวเหยียดล้นออกนอกภาพ

**ข้อเสียที่ยอมรับ:** ตัดคำผิดหลักภาษา (คำอาจขาดกลางคำ) การตัดที่ถูกต้องต้องใช้ ICU segmenter หรือ `Intl.Segmenter` ซึ่งเพิ่มความซับซ้อน

**ควรอัปเกรดเมื่อ:** เจ้าของอ่านแล้วรู้สึกว่าตัดคำน่ารำคาญ → เปลี่ยนไปใช้ `Intl.Segmenter('th', {granularity:'word'})` ซึ่ง Chrome รองรับแล้ว

**ย้อนกลับ:** ง่าย ฟังก์ชันเดียว

## D-006 · Gemini ใช้ alias `-latest` ห้าม pin เวอร์ชัน
**2026-08-15 · `spike/src/ocr/GeminiVisionReader.ts`**

**ทำไม:** `gemini-2.5-flash-lite` ที่ล็อกไว้ในเอกสารตั้งแต่วันแรก **คืน 404 "no longer available to new users"** ตอนทดสอบจริง Google ปิด point release แต่ alias ยังตามรุ่นปัจจุบันเสมอ

**สำคัญเป็นพิเศษเพราะจะแจกให้เพื่อน** — เพื่อนที่ติดตั้งอีก 6 เดือนข้างหน้าจะเจอ 404 โดยไม่รู้สาเหตุ และคุณต้องนั่งไล่แก้ทีละคน

**ย้อนกลับ:** ง่าย แต่**ไม่ควร**

## D-005 · Gemini vision แทน manga-ocr เป็นทางหลัก
**2026-08-15 · ดูรายละเอียดเต็มใน [ADR-001](ADR-001-ocr-runtime.md)**

**ทำไม:** วัดจริงได้ **5.27 วิ/bubble** สำหรับ manga-ocr ในเบราว์เซอร์ = ~10 เท่าของงบ หน้าที่มี 17 bubble ใช้ 53 วินาที ทำ auto-translate ไม่ได้เลย
ส่วน Gemini เป็น multimodal อ่าน+แปลได้ในคำขอเดียว → **2.5 วิ/หน้า** และไม่ต้องโหลดโมเดล 117 MB

**เก็บ PP-OCR detection ไว้ในเครื่อง** ไม่ให้ Gemini เดา bbox เพราะ overlay ดีได้เท่าที่พิกัดดี และ detection เร็วอยู่แล้ว (120 ms) แถมฟรี ไม่กินโควตา

**ไม่ทิ้ง manga-ocr** — ยังเป็นทางเลือก offline และเป็นฐานของ Local Service ในอนาคต

**ย้อนกลับ:** ปานกลาง — interface `TextRecognizer` รองรับทั้งคู่อยู่แล้ว สลับได้จาก dropdown

## D-004 · แยก `dilate()` ก่อน connected components
**2026-08-15 · `spike/src/core/components.ts`**

**ทำไม:** ตัวอักษรญี่ปุ่นแต่ละตัวเป็นก้อนหมึกแยกกัน CC บน probability map ดิบจึงได้ **หนึ่ง component ต่อหนึ่งตัวอักษร** ไม่ใช่ต่อบรรทัด ผลคือ kana เดี่ยวๆ กลายเป็น "bubble" ของตัวเอง ถูกส่งไปแปลเดี่ยวๆ แล้วได้ผลไร้ความหมาย ขณะที่ประโยคจริงไม่เคยถูกประกอบขึ้นมา

PaddleOCR ตัวจริงแก้ด้วย polygon unclip — สำหรับกล่องแนวแกน การ dilate mask ก่อนให้ผลเทียบเท่าและง่ายกว่ามาก

**radius ต้องเล็ก** พอเชื่อมตัวอักษรในคอลัมน์เดียวกัน แต่**ต้องไม่**เชื่อมสองคอลัมน์เข้าด้วยกัน — การตัดสินใจนั้นเป็นหน้าที่ของ `grouping.ts`

**ย้อนกลับ:** ง่าย ตั้ง `dilateRatio: 0` คือปิด

## D-003 · คำนวณเรขาคณิตในพิกเซล ไม่ใช่ normalized
**2026-08-15 · `spike/src/types.ts`**

มีสอง coordinate space: `PixRect` (พิกเซล ใช้คำนวณ) และ `NormRect` (`[0,1]` ใช้เก็บ/ส่งต่อ)

**ทำไม:** ใน normalized space **x กับ y หารด้วยตัวหารคนละตัว** หน้า 3496×4960 → `w:0.05` = 175 px แต่ `h:0.05` = 248 px โค้ดที่เทียบ width กับ height (aspect ratio, ระยะห่าง, "บรรทัดนี้แนวตั้งไหม") จะ**ผิดแบบเงียบๆ** ไม่ crash ไม่ error แค่ผลเพี้ยน

กฎ: คำนวณในพิกเซล → แปลงเป็น normalized ครั้งเดียวตอนออกจาก pipeline → **ห้ามแปลงกลับ**

**ย้อนกลับ:** ยาก — เป็นสมมติฐานที่ `core/` ทั้งหมดตั้งอยู่บน

## D-002 · Cache แยก 2 store: `ocr` และ `translation`
**2026-08-14 · design §9**

handoff เดิมเสนอเก็บเป็นก้อนเดียว (`contentHash → {ocr, translation}`)

**ทำไมแยก:** เปลี่ยน translation provider ทีนึง OCR ที่แพงกว่า 10 เท่าจะโดนล้างทิ้งไปด้วย
**ของแถมที่ได้ฟรี:** ประโยคซ้ำที่โผล่ทั้งเรื่อง (ชื่อตัวละคร, `「なに！？」`) จะ hit cache **ข้ามหน้า ข้ามตอน ข้ามเว็บ** เพราะ key เป็น hash ของข้อความ ไม่ใช่ของรูป

**ย้อนกลับ:** ปานกลาง ต้องเขียน migration ของ IndexedDB

## D-001 · overlay ผูกกับ `imageHash` ไม่ใช่ DOM element
**2026-08-14 · design §3.2.1**

**ทำไม:** imhentai ใช้ `<img id="gimg">` ตัวเดียวตลอดทั้งเล่ม เปลี่ยนหน้า = สลับ `src` element ไม่หายไปไหน

ถ้าผูกกับ element (ซึ่งเป็นวิธีที่ธรรมชาติที่สุด) จะเกิดบั๊กที่**อันตรายกว่าไม่มีคำแปลเลย**: กดไปหน้า 4 แล้วคำแปลของหน้า 3 ยังค้างทับอยู่ → ผู้ใช้อ่านผิดโดยไม่รู้ตัว

**ย้อนกลับ:** ยาก — เป็นสมมติฐานของชั้น overlay ทั้งหมด

## หมายเหตุสำหรับ agent ที่มาทำต่อ

เมื่อคุณตัดสินใจอะไรที่**เจ้าของโปรเจกต์ไม่ได้สั่งไว้ชัดเจน** ให้เพิ่มรายการใหม่ไว้บนสุด ใช้เลข D-xxx ถัดไป และตอบให้ครบ 4 ข้อ:

1. ตัดสินใจอะไร (พร้อมไฟล์ที่เกี่ยว)
2. **ทำไม** — เหตุผลที่แท้จริง ไม่ใช่คำอธิบายว่าทำอะไร
3. ทางเลือกที่ไม่เลือก และทำไมถึงไม่เลือก
4. ย้อนกลับยากแค่ไหน (ง่าย / ปานกลาง / ยาก)

**อย่าบันทึก**การเลือกที่ชัดเจนอยู่แล้วหรือมีทางเดียว — log ที่มีแต่เรื่องไม่สำคัญจะไม่มีใครอ่าน
