## ⚠️ ข้อจำกัดที่สำคัญที่สุด ต้องอ่านก่อนเลือกโมเดล

### 1. คอขวดคือ "ภาษาไทย" ไม่ใช่ "uncensored"
โมเดล abliterated เกือบทั้งหมดเป็น fine-tune ที่เน้นอังกฤษ และ **การทำ abliteration มีโอกาสทำให้ความสามารถ multilingual แย่ลง**
โมเดลที่แปลญี่ปุ่น→อังกฤษได้ดีมาก อาจแปลญี่ปุ่น→ไทยได้แย่มาก
→ **ต้องทดสอบไทยเองเสมอ** อย่าเชื่อ benchmark ทั่วไป (ซึ่งแทบไม่วัดไทยเลย)

### 2. VRAM ชนกันระหว่าง OCR กับ LLM 🔴
ถ้า OCR รันบน **WebGPU** มันกิน VRAM ของการ์ดใบเดียวกัน (~0.5–1.5 GB)
**LLM 5.3 GB + WebGPU OCR = OOM บนการ์ด 6 GB**

ทางเลือก (เลือกอย่างใดอย่างหนึ่ง):
| แผน | OCR | LLM | ผล |
|---|---|---|---|
| **A (แนะนำสำหรับ MVP)** | WebGPU (VRAM เต็มที่) | **Gemini** (ไม่กิน VRAM) | เร็วที่สุด |
| B | WebGPU | local ≤ 3.5 GB | พอไหว ต้องคุม `num_ctx` |
| C | WASM/CPU | local ≤ 5.3 GB | OCR ช้าลง แต่ privacy 100% |

→ **นี่เป็นเหตุผลเชิงเทคนิคเพิ่มเติมที่ทำให้ MVP = Gemini เป็นการตัดสินใจที่ถูก**

### 3. Local จะช้ากว่า Gemini อย่างมีนัยสำคัญ
output ต่อหน้า ≈ JSON 300–500 tokens
- 4B @ ~50 tok/s → **~8–12 วิ/หน้า**
- 9B (spill ไป RAM) @ ~10 tok/s → **~40–60 วิ/หน้า** ❌ ใช้กับ auto-scroll ไม่ได้
- Gemini flash-lite → **~2–3 วิ/หน้า**

→ Local คือ **fallback สำหรับ privacy / เนื้อหาที่ Gemini ปฏิเสธ / ออฟไลน์** ไม่ใช่ตัวหลัก

## วิธีทดสอบก่อนตัดสินใจ (ทำได้ใน ~15 นาที ไม่ต้องรอ M6)

1. เลือก **30 bubble** จากมังงะที่จะอ่านจริง — ต้องมีทั้ง บทพูดธรรมดา / สแลง / เสียงประกอบ (オノマトペ) / ประโยคสั้นมาก (`え？`) / เนื้อหา NSFW
2. ป้อนด้วย prompt + JSON schema ตัวเดียวกับที่ออกแบบไว้ใน design §11.3
3. ให้คะแนน 3 แกน:
   - **JSON ถูก format ไหม** (ถ้าพังบ่อย = ใช้ไม่ได้เลย ไม่ต้องดูข้ออื่น)
   - **ไทยอ่านรู้เรื่องและเป็นธรรมชาติไหม** (ไม่ใช่แค่ "แปลถูก")
   - **ปฏิเสธกี่ครั้ง**
4. วัดเวลา/หน้า และดู VRAM ด้วย `nvidia-smi`

**เกณฑ์ผ่าน:** JSON ถูก ≥ 95% · ไทยอ่านรู้เรื่อง ≥ 80% · ไม่ปฏิเสธ · ≤ 15 วิ/หน้า

> ถ้าอยากทำ ผมเขียน script ทดสอบตัวนี้ให้ได้ตอนไหนก็ได้ ใช้เวลาไม่นานและช่วยตัดสินใจได้จริง

## หมายเหตุการตั้งค่า Ollama

```bash
# จำเป็น: ไม่งั้น extension เรียกไม่ได้ (CORS)
OLLAMA_ORIGINS=chrome-extension://*

# แนะนำสำหรับ 6 GB: กัน KV cache กิน VRAM จนล้น
OLLAMA_KV_CACHE_TYPE=q8_0
```
ใน request ให้ตั้ง `num_ctx` เท่าที่จำเป็นจริง (~8192) — ค่า default 256K จะจอง KV cache มหาศาล
